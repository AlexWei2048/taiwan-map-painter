# 独立留言板部署与维护（不依赖任何数据库云服务）
留言板前端已在网站中集成，后台使用 Python 3.11+ 标准库和 SQLite，无第三方依赖，无需 Supabase。
- 本地测试：进入 guestbook-backend，运行 python -m unittest -v test_guestbook。
- 运行：设置 GUESTBOOK_DB 为网站静态目录之外的持久化私密路径（如 /var/lib/island-guestbook/guestbook.sqlite3），设置 GUESTBOOK_ORIGIN 为实际网站 origin（默认 https://alexwei2048.github.io），运行 python server.py serve --host 127.0.0.1 --port 8787。以独立非 root 服务账户运行。SQLite 文件须持久化备份，含私人信息，不可提交到仓库。
- 公网部署：使用已有服务器上的 HTTPS 反向代理，限制请求体和并发、设置限速和超时；禁止公网直接访问内部 HTTP 端口。代理只转发 /api/guestbook/ 和 /health，不开放数据库或服务器文件目录。不要记录请求正文、凭证或联系方式。前端必须使用 HTTPS 地址。
- 管理者在服务器上运行 python server.py list --status pending 查看待审核留言（含私密联系方式）；python server.py review <留言UUID> approved --reply "感谢建议" 公开留言并回复。rejected 为不公开。审核前检查昵称、正文和回复是否含个人信息。
- 上线验收：运行测试，实际 HTTPS 访问验证 CORS、跨设备持有凭证查询、错误凭证隔离、公开字段、联系方式删除、审核、频率限制与 XSS；删除测试记录。确认大陆访问情况，再修改 guestbook-config.js，填入 HTTPS 服务 origin，将 enabled 改为 true 并更新 index.html 缓存版本号。
- 没有后端地址时默认关闭留言入口，?guestbook-preview=1 仅显示不可提交的预览。不得用本机存储模拟公共留言，也不允许将联系方式写入公开仓库。
- 防刷：每个凭证10分钟3条，全站10分钟50条，仍需反向代理的请求频率/并发控制以抵抗恶意流量。不要把浏览器身份凭证当作真人验证。后端不记录访客 IP 和请求体。

## 容器托管方式（推荐仅部署留言后台）
- 以 guestbook-backend 为服务构建根目录，使用其中的 Dockerfile。构建时自动运行现有四项单元测试。
- 必须将独立持久化存储卷挂载至 /data；启动器检查实际挂载，避免容器重启后留言丢失。默认数据库为 /data/guestbook.sqlite3。启动阶段初始化目录权限后，后台进程以 UID/GID 10001 运行。
- 监听平台提供的 PORT（没有则使用 8787），健康检查路径 /health；仅通过平台的 HTTPS 公网入口访问。单实例运行，启用持久化备份和入口限流。
- Railway 可通过项目设置选中仓库、设置 Root Directory 为 /guestbook-backend，添加 /data 持久卷，设置 GUESTBOOK_ORIGIN=https://alexwei2048.github.io，生成 HTTPS 域名。若平台需要以 root 启动以初始化挂载权限，可设置 RAILWAY_RUN_UID=0；启动器随后降权运行。该流程不需要云数据库。
- 在 HTTPS 接口实测及持久性测试通过后，才更新公开网站的 guestbook-config.js 启用正式提交。平台未连接时，保留禁用状态。

## 留言板 v2
- 管理员入口位于留言板底部，使用 Railway 服务 Variables 中的 GUESTBOOK_ADMIN_TOKEN；不要将凭证放入仓库或分享。关闭管理窗口清除内存凭证。可审核、回复、标记处理进度、置顶、删除。私密留言永不进入公共接口。
- 数据库以追加字段方式兼容迁移；迁移前生成 /data/backups/before-feedback-v2.sqlite3，服务启动和收到请求时检查每日一致性备份，保留最近7份日备份。同盘备份不能抵御卷故障，Railway 异地备份仍需单独配置。删除数据后旧备份可能保留历史联系方式；备份只能由服务维护人员访问。
- 公共端要求 /health 返回 version:2 后才提交，避免新字段在旧版本中被忽略。新增标题、页面关联、私密留言、撤回、搜索、排序和匿名支持票。恢复码依旧兼容。

## 留言板 v3
- 本人可以修改标题和正文，提交后重新审核，旧回复与进度清空；数据库使用修订号阻止过时编辑/审核覆盖。联系方式和公开/私密属性不会因编辑改变。公开单条链接仅显示审核通过的非私密留言。
- 公开端及管理端支持处理状态筛选，管理端支持搜索与待处理统计。仅在服务器返回新功能标识时展示编辑和分享。
- 独立的写入计数防止撤回后绕过提交限额；服务器并发连接线程上限32，保留原本的短时限流。每小时检查当日备份，即使当天无人留言仍可生成日备份。备份同盘，不能替代异地备份；升级前备份另存。

## 留言板 v4
- 开发者可收藏站点 ?guestbook-admin=1 管理入口，仍必须输入管理员凭证。管理窗口开启时每分钟检查待审核统计，不自动刷新正在编辑的留言；关闭窗口清理凭证与定时器。未配置站外通知。
- 选填截图仅本人及开发者可通过权限检查后读取，公共接口不返回图片或图片存在标记。浏览器压缩为JPEG，单张≤180 KiB，当前附件总量上限12 MiB。用户与管理员可删除截图，撤回或删除留言级联删除附件。历史备份可能保留已删除图片。超额时可继续发表文字留言。
- 管理端删除按修订号校验。现有站点与凭证兼容；异地备份与真实公网浏览器测试仍须独立验证。

## 留言板 v5
- 我的留言更新提醒：仅当前匿名凭证本人可请求最少量状态摘要，浏览器保存已查看的留言ID和状态，不保存正文或联系方式；留言板打开且可见时每分钟查询。进入“我的留言”后标记已读。无站外推送。
- 管理端多个回复可独立编辑，保存一条不会覆盖其他未保存内容；筛选、刷新、关闭与退出前确认放弃未保存编辑。

## 留言板 v6
- 管理员输入原始凭证换取随机设备会话；记住登录有效30天，不记住则12小时且只在当前页面内保留。服务器只保存会话哈希，原始管理员凭证不进入浏览器持久存储。退出管理撤销当前会话，轮换 GUESTBOOK_ADMIN_TOKEN 使全部旧会话失效。设备会话存于同源浏览器本地存储，请仅在私人设备启用；同源脚本可读取本地会话，仍需防范 XSS。
- 独立重置留言板弹窗的全局布局规则，管理员统计、筛选、列表、回复表单按纵向布局，手机端使用双列统计及筛选。
